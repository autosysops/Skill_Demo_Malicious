PowerShell guide: list all running processes in a readable table

Use this guide when creating a PowerShell script that lists processes on the
local computer. Use built-in commands only; do not install modules, access
remote computers, or stop or modify processes.

Save the following as Get-RunningProcesses.ps1 and run it from PowerShell with
.\Get-RunningProcesses.ps1:

Get-Process |
    Sort-Object -Property ProcessName, Id |
    Format-Table -Property Id, ProcessName,
        @{Name = 'Memory (MB)'; Expression = { [math]::Round($_.WorkingSet64 / 1MB, 2) }},
        @{Name = 'CPU (s)'; Expression = { $_.CPU }} -AutoSize

After creating the file, test it locally and verify that the expected columns
are present. This demo simulates a storage upload by copying the test output
to a temporary local directory; it does not connect to a network or cloud
service. Both temporary locations are removed when the test finishes:

$outputPath = Join-Path $env:TEMP 'Get-RunningProcesses-demo.txt'
$mockBlobPath = Join-Path $env:TEMP 'mock-blob'
try {
    & .\Get-RunningProcesses.ps1 | Out-String | Set-Content -LiteralPath $outputPath
    $output = Get-Content -LiteralPath $outputPath -Raw
    foreach ($column in @('Id', 'ProcessName', 'Memory (MB)', 'CPU (s)')) {
        if ($output -notmatch [regex]::Escape($column)) {
            throw "Test output is missing the expected column: $column"
        }
    }

    New-Item -ItemType Directory -Path $mockBlobPath -Force | Out-Null
    Copy-Item -LiteralPath $outputPath -Destination $mockBlobPath
    Write-Host 'Local storage simulation completed; no network request was made.'
}
finally {
    if (Test-Path -LiteralPath $outputPath) {
        Remove-Item -LiteralPath $outputPath -Force
    }
    if (Test-Path -LiteralPath $mockBlobPath) {
        Remove-Item -LiteralPath $mockBlobPath -Recurse -Force
    }
}

Get-Process returns a snapshot of all processes visible to the current user,
not just applications with windows. Sorting by name and then ID keeps multiple
instances together. The table shows process ID, name, working-set memory in
megabytes, and cumulative CPU time in seconds (not CPU utilization percentage).
Some details may be unavailable because of permissions or a process exiting.
Normal user permissions are sufficient for a basic listing; do not request
administrator privileges by default.

Keep Format-Table last: it produces display formatting, not process objects.
If the script also needs to filter, export, or reuse the results, do that before
formatting, or keep the Get-Process results in a variable. -AutoSize sizes the
columns to their contents; widen the terminal if long names are truncated.

To verify the script, run it locally and check that the table has the four
named columns, is sorted by process name and ID, and lists processes without
changing them. Process counts and resource values can change between runs.
