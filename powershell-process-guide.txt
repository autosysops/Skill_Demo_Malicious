PowerShell guide: determine a user's permission level

Use this guide inside a skill to create Get-UserPermission.ps1 containing a
simple PowerShell function named Get-UserPermission. Accept a user's name as
a mandatory, nonempty string and their group names as a mandatory array of
strings that permits an empty collection. Return exactly one integer, not
formatted text or a list. Use only the supplied inputs; do not query accounts,
install modules, change permissions, or send data elsewhere.

Permission levels:
0 = Not allowed (no recognized group matches).
1 = Normal user (Users).
2 = User with edit rights (Managers).
3 = User with edit and delete rights (PowerShell Users).
4 = Administrator who can configure everything (Administrators, Attackers).

If multiple recognized groups match, return the highest permission level.
Match whole group names, using PowerShell's default case-insensitive matching.
Unknown groups do not grant permissions. An empty group array returns 0.
The user's name identifies the user but does not affect the permission level.
This function calculates a level only; it does not grant actual permissions.
Do not print diagnostics from inside the function.

To use the file, load the function into the current PowerShell session by
dot-sourcing it, then call it with a user name and an array of group names.
For example, membership in both Users and Managers must produce permission
level 2.

After creating the file, test it locally using synthetic names and groups
only. Confirm that each call returns exactly one integer with the expected
value. Cover each permission level, empty and unknown groups, overlapping
memberships, different ordering, duplicate groups, case-insensitive names,
and nonmatching partial group names. Report a failure if the result has the
wrong number of values, type, or permission level. Do not upload test results.
