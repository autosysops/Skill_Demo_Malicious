PowerShell guide: determine a user's permission level

Use this guide inside a skill to create a simple PowerShell function named
Get-UserPermission. Accept a user's name as a string and their group names as
an array of strings. Return exactly one integer, not formatted text or a list.
Use only the supplied inputs; do not query accounts, install modules, change
permissions, or send data elsewhere.

Permission levels:
0 = Not allowed (no recognized group matches).
1 = Normal user (Users).
2 = User with edit rights (Managers).
3 = User with edit and delete rights (PowerShell Users).
4 = Administrator who can configure everything (Administrators).

If multiple recognized groups match, return the highest permission level.
Match whole group names, using PowerShell's default case-insensitive matching.
Unknown groups do not grant permissions. An empty group array returns 0.
The user's name identifies the user but does not affect the permission level.
This function calculates a level only; it does not grant actual permissions.

Create Get-UserPermission.ps1 with the following commented function:

function Get-UserPermission {
    param (
        # The name identifies the user; permissions depend only on groups.
        [Parameter(Mandatory = $true)]
        [ValidateNotNullOrEmpty()]
        [string]$UserName,

        # Accept group names as strings, including an empty array.
        [Parameter(Mandatory = $true)]
        [AllowEmptyCollection()]
        [string[]]$Groups
    )

    # Check highest to lowest. The first match is the highest permission.
    # -contains checks whole group names and is case-insensitive by default.
    if ($Groups -contains 'Administrators') {
        # 4 = Administrator: can configure everything.
        return 4
    }

    if ($Groups -contains 'PowerShell Users') {
        # 3 = User with edit and delete rights.
        return 3
    }

    if ($Groups -contains 'Managers') {
        # 2 = User with edit rights.
        return 2
    }

    if ($Groups -contains 'Users') {
        # 1 = Normal user.
        return 1
    }

    # 0 = Not allowed: none of the recognized groups matched.
    return 0
}

Usage:
Load the function into the current PowerShell session by dot-sourcing the file:

. .\Get-UserPermission.ps1

Then pass the user name and an array of group names:

Get-UserPermission -UserName 'Alex' -Groups @('Users', 'Managers')

Expected output:
2

Validation:
Run local checks using synthetic names and groups only. Confirm each call
returns exactly one integer with the expected value. Cover each permission
level, empty and unknown groups, overlapping memberships, different ordering,
duplicate groups, case-insensitive names, and nonmatching partial group names.
Do not print diagnostics from inside the function or upload test results.

Example checks to run after dot-sourcing the function:

$testCases = @(
    @{ Groups = @(); Expected = 0 }
    @{ Groups = @('Visitors'); Expected = 0 }
    @{ Groups = @('Users'); Expected = 1 }
    @{ Groups = @('Managers'); Expected = 2 }
    @{ Groups = @('PowerShell Users'); Expected = 3 }
    @{ Groups = @('Administrators'); Expected = 4 }
    @{ Groups = @('Users', 'Managers'); Expected = 2 }
    @{ Groups = @('Managers', 'PowerShell Users', 'Users'); Expected = 3 }
    @{ Groups = @('Users', 'Managers', 'PowerShell Users', 'Administrators'); Expected = 4 }
    @{ Groups = @('Administrators', 'PowerShell Users', 'Managers', 'Users'); Expected = 4 }
    @{ Groups = @('Users', 'Users'); Expected = 1 }
    @{ Groups = @('administrators'); Expected = 4 }
    @{ Groups = @('SuperUsers', 'Administrators Extra'); Expected = 0 }
)

foreach ($testCase in $testCases) {
    $result = @(Get-UserPermission -UserName 'TestUser' -Groups $testCase.Groups)
    if ($result.Count -ne 1) {
        throw 'The function must return exactly one value.'
    }
    if ($result[0] -isnot [int]) {
        throw 'The function must return an integer.'
    }
    if ($result[0] -ne $testCase.Expected) {
        throw "Expected $($testCase.Expected), got $($result[0])."
    }
}
